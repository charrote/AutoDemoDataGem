> 评审对象：`docs/03.实现/43-首启设置向导.md`（对应《02.技术实现方案.md》§9 任务 4.3）
> 评审人：Agent-395-Hermes ｜ 日期：2026-09-21
> 评审维度：合理性 / 实现与运营风险 / 后续成本（统一评审报告见 [README.md](./README.md)）

## 结论

**⚠️ 有条件通过** — 「Web 先启动 + 数据库 Options」的设计对部署友好；但内置 MySQL 的拉起方式（容器内 `docker compose up`）在权限上有问题，且与 00/11 的启动顺序需统一。

## 1. 合理性

- 「web/api 不依赖 DB 启动 → 首启向导 → 选数据库模式 → 初始化」的两阶段模型，解决了「先有鸡还是先有蛋」（api 需要 DB，但 DB 连接信息要在向导里填）的部署难题，设计正确。
- 数据库 Options 二选一（自带 MySQL / 已有 MySQL）覆盖两种部署场景，对「兼容本地已有 MySQL」的产品承诺是落地。
- 「已有 MySQL 权限不足 → 导出建表 SQL 兜底」是务实的降级，正确。

## 2. 实现风险

- **内置 MySQL 的拉起方式有权限问题**：方案 §8.2 写「后台 `docker compose up -d --profile builtin-db db`」——**API 容器内无法直接调用宿主机的 docker compose**（需要挂载 docker.sock，这是巨大的安全暴露）。建议改为：
  - 方案 A：向导选「自带 MySQL」时，**在宿主机上手动执行** `docker compose up -d --profile builtin-db db`（向导提示命令，用户复制执行），api 轮询等待 db 健康后初始化；
  - 方案 B（推荐）：把 db 服务从 profile 改为**默认启动**（compose up 时 db 一起起），「已有 MySQL」模式只是 api 不连内置 db、连外部 db——内置 db 白起但不影响（浪费一点资源，换取部署简单）。
  方案 B 最简单：`docker compose up -d` 起 web+api+db，向导只决定「api 连哪个 db」。
- **与 00/11 的启动顺序**（R1 联动）：api 启动需要 VAULT_KEY（11 fail-fast）。向导阶段 api 还没初始化 DB，但 VAULT_KEY 是 env 静态配置，不依赖 DB——所以 VAULT_KEY 必须在 .env（compose 启动前）就配好。这与 00 的「.env 占位，不设不生效」一致，但要明确：**首启向导不解决 VAULT_KEY 缺失问题**（那是部署前提，不是向导内容）。
- **初始化（建库+建表+migrate）的幂等性**：用户可能重复点「初始化」（误操作/网络重试）。建议：`CREATE DATABASE IF NOT EXISTS` + `migrate` 幂等（Alembic 天然幂等）+ `settings.initialized` 标记防重复。
- **「导出建表 SQL」兜底**：导出的 SQL 要包含建库 + 建表 + 索引，用户手动执行后点「重新检测」。这个 SQL 要版本化（随 migrate 版本走），不能是静态文件。

## 3. 运营风险

- **首启向导是未鉴权入口**：`/api/status` 和向导页在「未初始化」状态是公开访问的（还没注册）。若部署在公网（nat.ywapi.com），任何人都能访问向导、触发「初始化」——**这是初始化阶段的竞态/滥用风险**。建议：
  - 初始化操作加「一次性 token」（启动时生成，显示在 api 日志里，用户填向导才能初始化）；或者
  - 部署时只暴露内网（nginx 反代加 IP 白名单），公网走 HTTPS + 后续鉴权。
  MVP 单机内部用可接受，但阶段 4 对外开放前必须解决。
- 向导页暴露「数据库模式 / 连接信息」——未初始化前这些是公开信息，风险低（还没数据），但要意识到。

## 4. 后续成本

- 一次性部署功能，无持续维护。
- 「已有 MySQL」的兼容分支是长期成本（要测试多种 MySQL 版本/权限组合），MVP 只测 QM-AI 同款 MySQL 8.0 即可。

## 5. 整改建议

| # | 建议 | 优先级 |
|---|------|--------|
| 1 | 内置 MySQL 改默认启动（方案 B），去掉「容器内调 docker compose」 | 高 |
| 2 | 初始化操作加一次性 token / 部署限内网（防未鉴权初始化） | 高 |
| 3 | 初始化幂等（IF NOT EXISTS + migrate 幂等 + initialized 标记） | 中 |
| 4 | 导出建表 SQL 随 migrate 版本走 | 低 |

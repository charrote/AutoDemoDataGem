# 30 · QM-AI连接器 — 评审

> 评审对象：`docs/03.实现/30-QM-AI连接器.md`（对应《02.技术实现方案.md》§9 任务 3.0）
> 评审人：Agent-395-Hermes ｜ 日期：2026-09-21
> 评审维度：合理性 / 实现与运营风险 / 后续成本（统一评审报告见 [README.md](./README.md)）

## 结论

**⚠️ 有条件通过** — 双通道设计是 MVP 灵魂，方向正确；但这是全项目**外部依赖最重**的一张卡（Q1/Q2 未核实），卡内验收标准与前置条件需要收紧。

## 1. 合理性

- 主数据/历史检验 → DB，活跃/SPC/8D 流程态 → API，SPC/KPI/不良率 → compute（触发重算+校验）：与产品方案 §5 的「按数据性质自动选路」一一对应，是产品「和灌数脚本的区别」的落地。
- 核实后只改 yaml 配置（schema.yaml / api_map.yaml / scenes/），不动核心引擎——解耦设计正确，Q1/Q2 的不确定性被隔离在连接器内。

## 2. 实现风险

- **Q1/Q2 是硬前置，但卡片把它和「填 yaml」混在同一个进度清单里**：Q1 依赖 YOO 确认 Swagger + 孔明抓取，Q2 依赖本地 `qmai-full.sql`。这两个外部输入不到位，本卡只能完成「空配置骨架」。建议把进度拆成「骨架（不依赖 Q1/Q2）」和「内容填充（依赖 Q1/Q2）」两段，前者可并行开工，后者阻塞。
- **「本地 QM-AI 有 qmai-full.sql + backend/ 源码」是外部事实**：评审无法核实该文件是否真实存在、是否最新。这是全方案最大的未验证假设——若 schema 与实际不符，DB 通道的字段映射全部返工。建议：Q2 核实动作 = 用 `qmai-full.sql` 起一个临时 MySQL，跑一遍连接测试（12）+ schema 探测，作为本卡第一验收项，而不是「读文件」。
- **api_map.yaml 的「调用顺序/依赖」是专家知识**：8D 流程（create → update_status → …）的每一步接口签名、状态机转移、必填参数，Swagger 给不了（产品 §6 已明确「仍需人工标注」）。这部分工作量被低估的风险最高——38 个 Controller 的写接口里，哪些是「安全可写」、调用顺序是什么，需要逐个实测。建议：验收标准加「api_map 中每个写接口都有实测记录（请求/响应样例）」，没有实测的接口不允许进 scenes。
- **compute 路由的「触发重算 + 校验」**：触发 SPC/KPI 重算的接口是否存在？若 QM-AI 没有暴露重算接口，compute 路由就落空——只能退化成「直接写看板表」（这又回到「插库假死」）。这是双通道证明的关键风险点，Q1 核实时必须确认。

## 3. 运营风险

- **对真实 QM-AI 的写操作**：本卡的「实灌一次」（32 联动）是对生产 QM-AI 的写操作。若 QM-AI 是多人共用的演示环境，灌入的数据会污染其他人的演示。运营上需要：确认一个专用 QM-AI 实例（或演示前重置流程写进 SOP）。
- Swagger 仅 Development 开启（Q3）：若演示环境是 Production，swagger 抓不到 → 42 的自动发现失效，退回手动映射。这不阻塞本卡（手动映射是兜底），但影响阶段 2 的「70% 自动化」承诺。

## 4. 后续成本

- **本卡是后续成本最高的单卡**：每支持一个新系统（EM-AI/MES）都要重复 Q1/Q2 核实 + yaml 填充 + 实测。MVP 只做 QM-AI，但路线图阶段 3 要 2 个连接器——每连接器的核实成本（读源码 + 实测接口 + 标语义）预计 1-2 人天，要计入排期。
- 连接器 yaml 的维护：QM-AI 升级（接口变更/schema 变更）→ yaml 失效 → 重新核实。这是 SaaS 化的持续成本，MVP 阶段可忽略，但要在 README 标注「连接器版本与目标系统版本绑定」。

## 5. 整改建议

| # | 建议 | 优先级 |
|---|------|--------|
| 1 | 进度拆「骨架 / 内容填充」两段，骨架不依赖 Q1/Q2 可并行开工 | 高 |
| 2 | Q2 验收 = 用 qmai-full.sql 起临时库跑通连接测试 + schema 探测（不是读文件） | 高 |
| 3 | api_map 每个写接口须有实测记录（请求/响应样例）才能进 scenes | 高 |
| 4 | Q1 核实时确认「compute 重算接口」是否存在，不存在则提前决策退化方案 | 高 |
| 5 | 运营 SOP：专用 QM-AI 实例 / 演示前重置流程 | 中 |

### 1.1 跨卡问题决议（R1–R8，逐项拍板）

> 以下为**建议决议**，供需求方确认。确认后写回对应任务卡的「关键实现点」并更新 `docs/02` 相关章节，作为后续实现的唯一口径。

| **R4** | API 通道 manifest/重置缺口 | manifest：有 ID 记 ID，无 ID 记「接口 + payload 指纹(sha256)」；重置分级：DB 通道精确删，API 通道有删除接口则删、无则标记「不可自动重置」(UI 明示)；Q1 实测须列出「哪些写接口可删/可回滚」 | 21 / 41 / 30 |

## 4. 关键路径与缓冲

```
M0 决议(0.5-1h) ─┬─> M1(5-9h) ─> M2(4-7h) ─┐
                  └─> Q1/Q2 核实(并行,不确定) ─┴─> M3(5-10h + 等待) ─> M4(7-14h)
```

- **最短路径**（Q1/Q2 快速通过）：M0 + M1 + M2 + M3 + M4 ≈ **21.5–41 人时**（纯开发，不含外部等待）。
- **关键路径风险**在 M3：若 Q1/Q2 各多花 2–3 天，M3 整体顺延。建议 M1/M2 期间把 Q1/Q2 的「骨架」先搭好（schema.yaml/api_map.yaml 的空白结构），核实到位后只填内容，压缩 M3 返工。
- **验证缓冲已含**：每卡 ×1.5；M3 额外建议 +1 天（端到端联调 + 「看板活」回归脚本调试）。

## 5. 阶段 4（开放注册上线）前置 checklist

> MVP（M1–M4）是**内部/内网**使用。阶段 4 对外开放前，以下 checklist 全部通过才上线。

- [ ] **HTTPS / TLS**：nginx 上证书（nat.ywapi.com 公网域名；JWT 存 localStorage，HTTP 明文 = 凭证可被中间人截获）
- [ ] **注册限流**：同 IP 限次（防批量垃圾注册）
- [ ] **登录限流**：撞库防护（同账号/同 IP 失败次数阈值 + 退避）
- [ ] **邮箱验证**：注册后邮箱激活（防垃圾账号）
- [ ] **未鉴权入口收敛**：S6 的一次性 token / 内网限制在公网下必须生效
- [ ] **SaaS 自库备份**：MySQL 定时 `mysqldump` + 恢复演练（users/systems/runs/manifest 是核心资产）
- [ ] **密钥保管 SOP**：VAULT_KEY/JWT_SECRET/MYSQL_ROOT_PASSWORD 的持有方、离线备份、轮换流程（R8 的 key_id 支持轮换）
- [ ] **磁盘 / 资源监控**：MySQL 数据增长 + 机器负载（与 MES-v24 共享）告警
- [ ] **镜像更新 / 漏洞 patch** 流程
- [ ] **运维 SOP**：演示日 SOP（专用实例 + 演示前完整 Run + 截图存档 + 不再动）；测试与演示环境分开（目标系统会把异常登录当安全事件）
